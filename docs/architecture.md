# Архитектура и границы

## Поток запроса

MAUI → HTTP Controller / SignalR Hub → Application service → GovorDbContext → PostgreSQL. Медиа-сервис сохраняет бинарные данные через LocalStorageService; ChatNotificationService отправляет SignalR-события и push через Firebase.

| Проект | Ответственность сейчас |
| --- | --- |
| Govor.API | Маршруты, хабы, авторизация, DI, преобразование ошибок и DTO |
| Govor.Application | Сценарии пользователей, друзей, сообщений, медиа и push |
| Govor.Contracts | HTTP/SignalR запросы, ответы и DTO |
| Govor.Domain | Сущности, DbContext, EF-конфигурации и миграции |

Это многослойное приложение, но Domain уже зависит от EF Core и содержит инфраструктуру БД. Не следует описывать его как полностью независимую доменную модель.

## Хранение и идентификаторы

PrivateChat связывает UserAId и UserBId. Message хранит SenderId и полиморфный RecipientId: ID PrivateChat для RecipientType.User или ID ChatGroup для RecipientType.Group. Ошибки возникают там, где этот ID сравнивают с ID пользователя.

Роль access token получается из приглашения пользователя (`Invite.IsAdmin`), хотя есть отдельная сущность Admin. Нужен один источник истины для ролей.

## Состояние соединений

ConnectionStore и OnlineUserStore — singleton в памяти одного процесса. Подключения автоматически вступают в группы пользователя, его чатов и групп. Перезапуск очищает это состояние; несколько инстансов без общего решения для SignalR и presence не имеют согласованного состояния.

## Рекомендуемые решения

1. Ввести общую проверку участия в конкретном чате и применять её к истории, Send, Read, медиа и событиям.
2. Разделить команды и чтение: создание чата и смена пароля не должны выполняться GET-запросами.
3. Возвращать только DTO, особенно для криптосессий и медиа.
4. Описать ошибки единым контрактом, сохранив совместимость с MAUI.
5. Для доставки отделить сохранение сообщения от внешних уведомлений: outbox и повторная доставка с дедупликацией.
6. Принять отдельное решение о E2EE: протокол, проверка ключей, несколько устройств, восстановление и миграция существующих сообщений.

Это предложения, они не внедрены в рамках переписывания документации.
